# Chai et al. (2019) 详细阅读笔记

论文：Shushan Chai, Qinghuai Liang, Simin Zhong. "Design of Urban Rail Transit Network Constrained by Urban Road Network, Trips and Land-Use Characteristics." Sustainability, 2019.

本笔记关注这篇论文对“轨道交通线网/线位规划”的可复用部分：输入数据、优化目标、约束、算法、案例数据，以及它对 CS240 项目的启发。

## 1. 论文解决的问题

这篇论文研究的是城市轨道交通网络设计问题。作者认为传统实践中，线路走向、线网形态、客流走廊、土地利用之间的匹配经常依赖定性判断，因此希望建立一个可计算的优化模型。

它的核心问题可以概括为：

给定城市道路网、预测 OD 客流、交通小区、土地利用强度、候选大客流节点和候选车站，在道路网约束下生成若干条轨道交通线路，使线路网络尽量：

1. 沿着可建设道路和主要客流走廊布设；
2. 匹配城市出行需求空间分布；
3. 匹配城市土地利用空间分布；
4. 提高单位线路长度的客流周转效率；
5. 降低乘客换乘规模，提高出行直达性。

这不是单条线路选线，而是多条线路组成的线网设计。不过它的建模思想可以简化到我们项目里的“新增一条线/一组候选线路走廊选择”。

## 2. 输入数据

论文把输入分成几类。

### 2.1 城市道路与候选基础网络

作者认为轨道交通线路通常沿道路布设，只有特殊情况下才穿越地块。因此先构造一个 basic network，用来限制线路搜索范围和方向。

基础网络的构造依赖：

1. 城市道路网；
2. 主要客流走廊；
3. 大客流点，例如交通枢纽、公交换乘枢纽、公交首末站、铁路站、机场、区级中心、商业文化点、大型企业、大型居住区、旅游景点；
4. 满足轨道建设条件和用地要求的主干道路或补充道路。

作者不是直接在全城平面上搜索线路，而是先把城市路网抽象成一个候选拓扑图。这样可以大幅缩小搜索空间，也更符合“线路沿道路或走廊布设”的规划逻辑。

### 2.2 OD 出行需求

论文假设城市轨道交通客流需求已知。需求用 OD pair 表示：

- `W`：大客流点之间的 OD 对集合；
- `g_w`：OD 对 `w` 的客流需求；
- 交通小区的出行发生量 `P_i` 和吸引量 `A_i`；
- 交通小区出行强度 `S_i = P_i + A_i`。

OD 需求也用于构造主要客流走廊。作者使用 cobweb assignment 方法：

1. 根据预测客流生成交通小区之间的 OD desire lines；
2. 删除跨区 desire lines，保留相邻小区之间的 desire lines，形成 virtual cobweb；
3. 在 virtual cobweb 上做 all-or-nothing 分配；
4. 按客流累积规模识别主要客流走廊。

这一步很重要：它把 OD 矩阵转化成“哪些走廊值得布线”的空间约束。

### 2.3 土地利用强度

论文用人口和就业人口之和表示土地利用强度：

`P(.) = resident population + employed population`

也就是说，居住人口和岗位人口共同决定城市空间活动强度。这个设定和我们想用“人口数据 + 用地性质推断岗位数据”很贴近。

### 2.4 候选站点和候选线网参数

模型还需要：

- `N`：基础网络中的候选站点集合；
- `E`：基础网络中的候选区间集合；
- `N(i)`：站点 `i` 的邻接站点；
- `L`：候选线路集合；
- `d_ij`：候选区间 `{i,j}` 长度；
- `C_ij`：区间容量；
- `x_i, y_i`：站点坐标；
- 每条线路的最小/最大站点数；
- 每条线路的最小/最大长度；
- 线网中线路数量的最小/最大值；
- 站点重复度上限 `a`；
- 区间重复度上限 `b`；
- 相邻区间最小夹角 `c`；
- 出行匹配度下限 `mC_min`；
- 用地匹配度下限 `mF_min`。

## 3. 关键建模思想

### 3.1 站点结构重要性

作者把轨道网络看作复杂网络，用三类中心性描述站点的重要程度：

1. Degree centrality：站点与其他站点的直接连接程度；
2. Closeness centrality：站点到其他站点的平均接近程度；
3. Betweenness centrality：站点在其他站点最短路径中的中介作用。

综合站点重要性：

`I_i = w_1 DC_i + w_2 CC_i + w_3 BC_i`

这个指标后续用于计算“站点重要性分布”的重心和分形维度。

对我们来说，这部分可以保留，也可以简化。若项目重点是新增线路，站点重要性可以替换为：

- 是否为换乘站；
- 是否靠近高人口/高岗位区域；
- 是否服务高 OD 需求；
- 站点在已有线网中的可达性提升。

### 3.2 出行需求匹配：重心偏差

作者提出一个“线网与出行需求匹配度”指标。

首先计算两个重心：

1. 城市出行强度重心：由各交通小区的 `S_i = P_i + A_i` 加权得到；
2. 站点重要性分布重心：由候选轨道网络中各站点的重要性 `I_i` 加权得到。

如果两个重心距离越近，说明线网布局越贴近城市出行需求分布。

论文用 `mC` 表示出行匹配度，并把它作为约束：

`mC_min <= mC <= 1`

直观解释：不能生成一个虽然客流效率高、但空间上明显偏离主要出行需求分布的线网。

### 3.3 土地利用匹配：分形维度偏差

作者用分形维度来刻画土地利用强度和站点重要性在城市空间中的扩散形态。

做法大致是：

1. 以城市出行强度重心为中心画同心圆；
2. 按半径统计土地利用强度随距离增加的累积变化；
3. 对 `ln P(r)` 和 `ln r` 做线性回归，斜率作为土地利用强度的分形维度；
4. 城市不同方向发展不均衡，所以作者把城市划分成四个象限，分别计算分形维度向量；
5. 同样计算站点重要性分布的分形维度；
6. 比较两组分形维度向量，得到土地利用匹配度 `mF`。

约束为：

`mF_min <= mF <= 1`

直观解释：线网的空间展开形态应当和城市土地开发强度的空间展开形态相一致。

这部分数学上很有特色，但对课程项目来说可能偏复杂。我们可以把它作为“高级约束/扩展项”，或者简化为服务覆盖指标，例如高人口/高岗位栅格覆盖率、站点缓冲区服务人口、站点缓冲区服务岗位数。

## 4. 决策变量

论文的主要变量包括：

- `e_ij`：候选网络是否包含区间 `{i,j}`；
- `e^l_ij`：线路 `l` 是否包含区间 `{i,j}`；
- `v_i`：候选网络是否包含站点 `i`；
- `v^l_i`：线路 `l` 是否包含站点 `i`；
- `f^{wpl}_{ij}`：OD 对 `w` 在路径 `p`、线路 `l` 上是否经过区间 `{i,j}`；
- `f^{wpll'}`：OD 对 `w` 沿路径 `p` 是否从线路 `l` 换乘到线路 `l'`；
- `q_ij`：区间 `{i,j}` 的断面客流；
- `P_{wp}`：OD 对 `w` 选择路径 `p` 的概率。

这说明作者把线网设计和客流分配耦合在一起：线路怎么选会影响路径集合、路径时间、换乘、区间客流，反过来这些指标进入目标函数。

## 5. 目标函数

论文有两个目标，并用加权和合成单目标。

### 5.1 目标一：最大化单位网络长度客流周转量

公式含义：

`Z1 = total passenger-km / total network length`

也就是：

`Z1 = sum(q_ij * d_ij * e_ij) / sum(d_ij * e_ij)`

其中：

- `q_ij` 是区间断面客流；
- `d_ij` 是区间长度；
- `e_ij` 表示该区间是否被选入网络。

这个目标代表运营者视角：单位建设长度能承载多少客流周转。它比单纯最大化客流量更合理，因为会惩罚过长但收益不足的线路。

### 5.2 目标二：最小化线路间平均换乘客流

作者认为换乘越多，乘客便利性越差。第二个目标是最小化各线路之间的平均换乘客流规模：

`Z2 = transfer passenger volume averaged over line pairs`

它通过 OD 需求、路径选择概率和换乘变量累计得到。

这个目标代表乘客视角：希望线路结构提高直达性，减少换乘负担。

### 5.3 加权目标

两个目标被组合为：

`max Z = beta_1 Z1 - beta_2 Z2`

其中：

`beta_1 + beta_2 = 1`

案例中参数为：

- `beta_1 = 0.65`
- `beta_2 = 0.35`

这说明论文略偏重运营效率，但仍显式考虑乘客换乘便利性。

## 6. 客流分配与路径选择

论文采用 logit-based multi-path passenger flow assignment。

路径旅行时间由三部分组成：

`T_w^p = section travel time + dwell time + transfer time`

换乘时间还加入了换乘惩罚：

`transfer time = sum transfer_time_at_station * sensitivity_penalty`

然后定义有效路径：

`T_w^p <= (1 + H) * T_wmin`

其中 `H = 1.5`。也就是说，只考虑不比最短路径绕行太多的路径。

路径选择概率用 logit 模型：

`P_{wp} = exp(-theta * T_w^p) / sum exp(-theta * T_w^p)`

这一步能把 OD 需求分配到不同路径上，再得到区间断面客流 `q_ij` 和换乘客流。

对我们项目来说，如果时间有限，可以先简化为：

1. 每个 OD 只走最短时间路径；
2. 或者保留 top-k shortest paths；
3. 用 logit 分配客流；
4. 比较有无新增线路前后的总旅行时间、换乘次数和覆盖客流。

## 7. 约束条件

### 7.1 网络拓扑约束

主要含义：

1. 如果一条线路包含某个区间，那么区间两端站点必须在该线路上；
2. 网络视为无向图；
3. 一个区间可被多条线路共用；
4. 单条线路不能有分支，不能有环；
5. 一个站点最多被 `a` 条线路重复使用；
6. 一个区间最多被 `b` 条线路重复使用。

其中“不分支、不成环”很适合我们。如果做一条新增线路，可以直接要求候选解是一条 simple path。

### 7.2 客流守恒约束

对每个 OD 和路径：

1. 起点有净流出；
2. 终点有净流入；
3. 中间站流入等于流出；
4. 同一线路上不能反向回流。

这本质上是经典网络流约束。

### 7.3 城市特征匹配约束

两个匹配度必须达到下限：

- 出行需求匹配：`mC_min <= mC <= 1`
- 土地利用匹配：`mF_min <= mF <= 1`

案例中：

- `mC_min = 0.7`
- `mF_min = 0.65`

### 7.4 线形平顺约束

相邻两个区间之间的夹角不能太小：

`c <= angle <= pi`

这防止线路出现过急转弯。案例中最小夹角约为 5π/12，即 75 度。

这对线位规划很实用，可以直接作为几何约束。

### 7.5 网络规模约束

包括：

1. 每条线路的站点数上下限；
2. 每条线路长度上下限；
3. 线网线路数量上下限。

案例参数大致为：

- 每条线最少 8 个站、最多 15 个站；
- 每条线最短 15 km、最长 35 km；
- 线网最少 3 条线、最多 6 条线。

### 7.6 区间容量约束

每个区间上的分配客流不能超过区间容量：

`sum OD assigned flow on section <= C_ij`

案例中 `C_ij = 45000`。

## 8. 求解算法

论文指出该问题是 NP-hard，因为网络结构复杂、约束多、搜索空间大。作者采用基于模拟退火的邻域搜索算法。

### 8.1 邻域操作

有四类扰动：

1. 随机增加一条线路；
2. 随机删除一条线路；
3. 随机给某条线路增加一个区间；
4. 随机删除某条线路中的一个区间。

这些操作可以独立执行，也可以组合执行。

### 8.2 接受准则

设当前解为 `G_curr`，新扰动解为 `G_new`。

如果：

`f(G_new) > f(G_curr)`

则接受新解。

否则按 Metropolis criterion 以一定概率接受劣解：

`p = exp((f(G_new) - f(G_curr)) / T)`

随着温度下降，接受劣解的概率逐渐下降。

算法还维护一个 best-so-far 解 `G_best`。

### 8.3 案例参数

案例中：

- 退火降温率为 `0.9`；
- 最大迭代次数为 `500`；
- 乘客换乘敏感性参数设为 `0`。

## 9. 实证案例：包头中心城区

论文使用了真实城市案例：内蒙古包头。

数据规模：

- 城市总面积超过 2000 平方公里；
- 中心城区划分为 433 个交通小区；
- 选择了 64 个大客流点；
- 先通过 cobweb assignment 得到城市主要客流走廊；
- 再结合城市发展主轴和道路网构建 basic network。

土地利用处理：

- 预测长期规划年的交通小区土地利用强度；
- 以出行强度重心为中心；
- 每 500 m 画一圈；
- 按四个象限分别计算土地利用强度分形维度；
- 得到土地利用分形维度向量：

`D_P = (1.506, 1.509, 1.549, 1.131)`

优化结果：

- 最优目标值 `Z ≈ 8664.2`；
- 第一目标 `Z1 ≈ 32287`；
- 第二目标 `Z2 ≈ 35207`；
- 最优线网为 5 条线路；
- 总长度 `110.6 km`；
- 出行匹配度 `mC ≈ 0.947`；
- 土地利用匹配度 `mF ≈ 0.893`；
- 站点重要性重心与出行强度重心距离约 `973.9 m`。

作者认为得到的线网整体呈放射结构，中心区辅以网格结构，东西向为主轴，符合包头带状城市发展形态。

## 10. 对我们项目的启发

这篇论文非常适合作为我们轨交线路规划项目的核心参考，因为它天然连接了经典算法与现代城市数据。

### 10.1 可以直接借鉴的部分

1. 把道路网抽象成候选图；
2. 用 OD 矩阵识别主要客流走廊；
3. 将线路规划建模为图上的路径/子图选择；
4. 用单位长度客流收益衡量线路效率；
5. 用换乘次数或换乘客流衡量乘客便利性；
6. 加入线长、站点数、转角、容量、换乘等约束；
7. 用模拟退火或邻域搜索求解 NP-hard 组合优化问题。

### 10.2 对课程项目更稳妥的简化

为了更符合 CS240 项目“经典算法 + 可复现”的要求，可以把问题缩成：

在已有轨交网络和道路候选图上，选择一条新增轨交线路，使它在预算长度内最大化服务收益，并降低 OD 出行成本。

输入：

- 现有轨交站点和线路；
- 道路网/候选走廊图；
- 候选站点；
- 人口栅格或交通小区人口；
- 岗位强度；
- OD 矩阵；
- 线路长度预算；
- 最小转角约束；
- 与已有线路的换乘连接约束。

目标可设为：

`max captured_OD_benefit + served_population_jobs - construction_cost - transfer_penalty`

或者更贴近论文：

`max passenger_km_per_km - average_transfer_passengers`

经典算法可选：

1. 最短路/A*：计算 OD 在现状线网和新增线路后的出行成本；
2. k-shortest paths：生成候选线路；
3. prize-collecting path / budgeted maximum coverage：在线长预算内选择高收益路径；
4. dynamic programming：若候选线近似为有向无环走廊，可做预算约束路径 DP；
5. simulated annealing / local search：在线路节点序列上做邻域搜索；
6. min-cost flow 或 network flow：做客流分配的简化版本。

### 10.3 需要谨慎处理的部分

论文中的分形维度土地利用匹配很有特色，但实现和解释成本较高。如果项目周期紧，可以不作为主模型，只作为可选扩展：

- 基础版本：站点 800m 缓冲区覆盖人口/岗位；
- 进阶版本：计算新增线路服务区域与城市人口/岗位重心的偏差；
- bonus 版本：复现论文的土地利用分形维度匹配指标。

论文中完整线网设计变量很多，若完全复现，工程量会比较大。课程项目更适合把它改造成“新增线路路径优化”或“小规模候选线网优化”。

## 11. 可用于 proposal 的一句话总结

Chai et al. (2019) 将城市轨道交通线网设计建模为道路约束候选图上的组合优化问题：先根据 OD 需求和大客流点构造候选基础网络，再以单位线路长度客流周转量最大化和线路间换乘客流最小化为目标，并加入出行需求重心匹配、土地利用分形匹配、线长、站点数、转角、容量等约束，最后用基于模拟退火的邻域搜索在包头中心城区真实案例上生成 5 条线路、110.6 km 的优化线网。
